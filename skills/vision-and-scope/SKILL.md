# Навык: Vision and Scope (по Вигерсу)

## Цель

Создай профессиональный документ **Vision and Scope** в соответствии с шаблоном Карла Вигерса. Документ описывает, *почему* проект существует (бизнес-обоснование) и *что* входит в его границы — без погружения в детали реализации.

## Обязательные действия

1. **Прочитай шаблон** → `templates/vision-and-scope-template.md`
2. **Изучи пример** → `examples/vision-and-scope-example.md`
3. **Собери информацию** — если чего-то нет, задай уточняющие вопросы (не более 5 за раз)
4. **Заполни документ** строго по структуре шаблона
5. **Проверь качество** по чеклисту в конце этого файла

## Структура документа (7 разделов Вигерса)

### 1. Business Requirements (Бизнес-требования)

**1.1 Background and Strategic Opportunity**
- Краткая история проблемы или рыночной возможности
- Почему сейчас? Что изменилось?

**1.2 Business Opportunity**
- Описание рыночной возможности или внутренней проблемы
- Для кого создаётся продукт?

**1.3 Business Objectives and Success Criteria**
- Измеримые бизнес-цели в формате BO-N
- Критерии успеха (SMART: конкретные, измеримые, достижимые, актуальные, ограниченные по времени)
- Формат: `BO-1: [Глагол действия] [что] на [X%/единиц] к [дата/релиз]`

**1.4 Customer or Market Needs**
- Неудовлетворённые потребности пользователей
- Проблемы текущего решения (если есть)

**1.5 Business Risks**
- Идентифицированные риски в формате BR-N
- Вероятность и влияние
- Формат: `BR-1: [Описание риска]. Вероятность: [В/С/Н]. Влияние: [В/С/Н].`

### 2. Vision of the Solution (Видение решения)

**2.1 Vision Statement**
Используй формулу Джеффри Мура:
```
FOR [целевой пользователь]
WHO [нуждается в / имеет проблему]
THE [название продукта] IS A [категория продукта]
THAT [ключевая выгода / причина купить]
UNLIKE [основная альтернатива]
OUR PRODUCT [ключевое отличие]
```

**2.2 Major Features**
- Список ключевых возможностей системы в формате FE-N
- Формат: `FE-1: [Название возможности] — [краткое описание]`
- Связь с бизнес-целями (BO-N)

**2.3 Assumptions and Dependencies**
- AS-N: Допущения о среде, пользователях, технологиях
- DE-N: Внешние зависимости, от которых зависит успех

### 3. Scope and Limitations (Границы и ограничения)

**3.1 Scope of Initial Release**
- Что войдёт в первый релиз (v1.0)
- Связь с FE-N из раздела 2.2

**3.2 Scope of Subsequent Releases**
- Что отложено на v2.0, v3.0 и т.д.
- Критерии перехода между релизами

**3.3 Limitations and Exclusions**
- Явное перечисление того, что НЕ входит в scope
- Важно: защита от scope creep

### 4. Business Context (Бизнес-контекст)

**4.1 Stakeholder Profiles**
Краткая таблица. Подробные профили — в отдельном документе.
| Стейкхолдер | Роль | Интересы | Влияние |
|-------------|------|----------|---------|

**4.2 Project Priorities**
Матрица приоритетов Вигерса (Features vs. Quality vs. Schedule vs. Cost vs. Staff):

| Измерение | Ограничить | Оптимизировать | Принять |
|-----------|-----------|----------------|---------|
| Schedule  |           |                |         |
| Features  |           |                |         |
| Quality   |           |                |         |
| Cost      |           |                |         |
| Staff     |           |                |         |

**4.3 Deployment Considerations**
- Среда развёртывания
- Требования к миграции данных
- Обучение пользователей

### 5. (Опционально) Appendix

- Глоссарий
- Ссылки на связанные документы
- История изменений

## Чеклист качества Vision and Scope

Перед финализацией проверь каждый пункт:

### Бизнес-требования
- [ ] Все бизнес-цели (BO) измеримы и имеют конкретные цифры
- [ ] Риски (BR) оценены по вероятности и влиянию
- [ ] Указана целевая аудитория и её реальные потребности

### Vision Statement
- [ ] Использована формула Мура (или аналог)
- [ ] Чётко сформулировано отличие от конкурентов/альтернатив
- [ ] Vision statement умещается в 1–2 абзаца

### Фичи и Scope
- [ ] Каждая фича (FE) связана хотя бы с одной бизнес-целью (BO)
- [ ] Scope Subsequent Releases содержит элементы, явно исключённые из v1.0
- [ ] Раздел Limitations содержит хотя бы 3 явных исключения

### Структура
- [ ] Все разделы (1–4) заполнены
- [ ] Нет технических деталей реализации (это НЕ SRS)
- [ ] Документ понятен бизнес-спонсору без технического образования

## Частые ошибки — не допускай

❌ **Не смешивай Vision and Scope с SRS** — здесь нет функциональных требований, экранов, API  
❌ **Не пиши абстрактные цели** — вместо "повысить эффективность" пиши "сократить время обработки заявки с 3 дней до 4 часов к Q3 2025"  
❌ **Не забывай про ограничения** — раздел Limitations защищает команду от размывания рамок  
❌ **Не упускай стейкхолдеров** — пользователи ≠ покупатели ≠ спонсоры

## Вопросы для сбора информации

Если информации недостаточно, задай эти вопросы:

**О бизнесе:**
1. Какую бизнес-проблему решает этот продукт? Что происходит сейчас без него?
2. Как вы измерите успех проекта через 6–12 месяцев?
3. Какие главные риски угрожают проекту?

**О пользователях:**
4. Кто будет использовать систему? Перечислите типы пользователей.
5. Каковы самые большие болевые точки текущего процесса?

**О scope:**
6. Что точно должно быть в первом релизе?
7. Что точно НЕ входит в этот проект?
8. Каков deadline и бюджет?
